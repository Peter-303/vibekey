## 2. 麦克风选型（PRD 标为开放问题，必须二选一）

| 选型 | 需要引脚 | 固件驱动 | 评价 |
|---|---|---|---|
| **I2S 数字麦**（如 INMP441、SPH0645） | BCK / WS / DIN 三根 | `i2s_std` 驱动，最简单 | ✅ **推荐**。直接出 16bit PCM，无需外挂 codec，16kHz 采样率原生支持 |
| **PDM 数字麦**（如 MP34DT05） | CLK / DATA 两根 | `i2s_pdm` 驱动 | 也可，但 PDM 需抽取滤波，CPU 开销略高 |
| **模拟麦 + ADC** | 一路 ADC1 | ADC 连续采样 + 自建环形缓冲 | ❌ 不推荐。ESP32-S3 ADC 非线性明显、底噪大，16kHz 连续采样会持续占用 CPU 且与 WiFi 冲突 |

**建议**：直接选 I2S 数字麦，可显著降低 M4 风险，也不占 ADC。

## 3. ESP32-S3 引脚约束（填写时务必遵守）

- **GPIO 26–32**：模组内部用于 SPI Flash / PSRAM，**禁止分配**。
- **GPIO 19 / 20**：USB-OTG 的 D- / D+。若硬件的 USB-C 数据线接到这两颗（TinyUSB CDC 方案要求如此），则**不得再分配给其他信号**。
- **GPIO 43 / 44**：默认 UART0（ESP-IDF 日志口），保留给日志，不要占用。
- **GPIO 0**：Strapping 引脚（启动模式选择），一般不复用为按键。
- **GPIO 1 / 2 / 3**：部分模组的 JTAG 复用；若不用 JTAG 可作为普通 IO，但需确认没有冲突。
- **ADC1**：GPIO 1–10；**ADC2** 与 WiFi 冲突，采集时不可用 → 模拟麦必须走 ADC1。
- 按键建议加**硬件 RC 消抖或至少保留上拉**，与固件 15ms 软件消抖叠加效果更好。

## 4. 两个必须由硬件组确认的问题

| # | 问题 | 为什么重要 |
|---|---|---|
| Q1 | USB-C 的 D+/D- 是否接到 GPIO20/19（USB-OTG）？是否还接了 USB Serial/JTAG？ | 决定上位机烧录流程。若只有 OTG，进入下载模式后 COM 口会**跳变**（见设计文档 §7.1），上位机必须处理；若两者都没接，烧录得改走 UART0 + 外部 USB-TTL |
| Q2 | 模组是否带 **PSRAM**？ | 整包语音模式 60s 音频 = 1.92 MB，内部 RAM（约 512KB）放不下，必须落 PSRAM（见设计文档 §5.5） |
